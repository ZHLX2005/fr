## 簇 A — clock widget 深链 native 未接（任务 #1）

### 根因（已亲自读码确认，用户指出方向正确）

用户原话：「使用符号进入触发，连页面都不会进去，是不是本来该前缀匹配，你错误使用了等于判断，导致丢失」——**完全命中**。

1. **Dart 路由层是对的**：`fr_router.dart:41-53` `findHandler` 用 `authority == reg || authority.startsWith('$reg/')`（prefix 匹配，最长优先），`clock/widget-toggle` 已在 `bootstrap_routes.dart` 注册，能命中 `ClockWidgetToggleHandler`。
2. **native PendingIntent 也是对的**：`ClockWidgetProvider.kt:125-128` 发 `fr://clock/widget-toggle`，与注册 authority 一字不差。
3. **断点在 `MainActivity.kt:217-251` `handleIntent` 的 when 块**：
   - notion 用 `uriStr.startsWith("fr://notionimg")`（**prefix**，注释明确说「必须 startsWith，精确 == 会 miss」）
   - recorder 用 `uriStr.startsWith("fr://lab/demo/recorder")`（**prefix**）
   - **clock 用 `uriStr == "fr://clock" || uriStr == "fr://lab/demo/clock"`（等于判断，第 239-240 行）**
   - `fr://clock/widget-toggle` ≠ `fr://clock`，≠ 任何其它分支 → **when 无 else → 静默丢弃，什么都不做** = 用户看到「连页面都不会进去」。
4. **且 Dart/Kotlin 通道也缺对应方法**：`WidgetChannel.kt` 无 `navigateToClockWidgetToggle`；`main.dart:325-337` `FrMethodChannelTranslator` 无对应映射。

### 目标

让 `fr://clock/widget-toggle` 从 native 一路走到 Dart 路由，最终触发 `LabClockProvider.toggleLatestClock()`。

### 修法（3 文件 + 1 处 prefix 语义修正）

1. `WidgetChannel.kt`：
   - when 加 `"navigateToClockWidgetToggle" -> { onNavigateToClockWidgetToggle?.invoke(); result.success(null) }`
   - 加 `var onNavigateToClockWidgetToggle: (() -> Unit)? = null`
   - 加 `fun notifyNavigateToClockWidgetToggle() { channel.invokeMethod("navigateToClockWidgetToggle", null) }`
2. `MainActivity.kt` `handleIntent`：
   - **在 clock 分支之前**加更具体的 `uriStr.startsWith("fr://clock/widget-toggle") -> { widgetChannel.notifyNavigateToClockWidgetToggle() }`（必须在前，否则被 clock 分支的 `==` 之外的 path 兜底吞掉——实际当前 clock 分支是 `==` 不会吞，但顺序上更具体在前是正确写法）。
   - **同时把 clock 分支的等于判断改成 prefix**（与 notion/recorder 一致，防止将来再加 `fr://clock/xxx` 又丢包）：`uriStr.startsWith("fr://clock") || uriStr.startsWith("fr://lab/demo/clock") || uri.path == "/lab/demo/clock"`。
3. `lib/main.dart` `FrMethodChannelTranslator.translate`：
   - 加 `'navigateToClockWidgetToggle' => 'fr://clock/widget-toggle',`
   - 顶部文档注释的「已支持的 method」清单同步加一行。

### 验收

- 单测：`FrMethodChannelTranslator.translate` 对 `navigateToClockWidgetToggle` 返回 `fr://clock/widget-toggle`；且 `fr://clock/widget-toggle` 能被 `frRouter.findHandler` 命中 `ClockWidgetToggleHandler`（authority 匹配单测）。
- 真机：桌面 widget 点 toggle 按钮 → **能进入 app 的 clock 页** → 最新 clock 开始/暂停切换；点 widget 主体仍进 clock 页（原行为不回退）。
- flutter analyze 干净。

## 簇 B — calendar 进入闪屏（任务 #2）

### 根因（已读码确认）

- `calendar_demo.dart:40-50` `buildPage` 返回 `MultiProvider`，两个 provider 在此 `create`（**未在 main.dart 预热**，每次进页面重建）。
- `lab_calendar_provider.dart:30-38` 构造 → `_init()` → `await CalendarRepository.instance.init()`（**Hive 开箱 50-200ms**）→ `_loadAll()`。
- `lab_people_provider.dart:15-23` 同样 `await CalendarRepository.instance.init()`（重复等待）→ `_people = _repo.load()`。
- 首帧渲染时 `_events`/`_people` 都是空列表，`MonthView`/`YearView`/`PeopleView` **直接渲染真实数据、无 loading 占位** → 先画空网格，~0.1-0.2s 后数据到位重画 = 用户看到的「加载闪屏 + 组件闪烁」。

### 目标（用户拍板：B · 视图加 loading 占位）

不改启动流程、不预热；在 provider 暴露「是否加载完成」标志，视图在未加载完成时渲染 loading 占位（而不是先画一遍空数据再跳变）。

### 修法

1. `lab_calendar_provider.dart`：加 `bool _ready = false;` + `bool get ready => _ready;`，`_init()` 末尾（`_loadAll()` 之后）置 `_ready = true` 并 `notifyListeners()`。
2. `lab_people_provider.dart`：同样加 `ready` 标志（`_people = _repo.load()` 之后置位）。
3. 视图层：`month_view.dart` / `year_view.dart` / `day_view.dart` / `people_view.dart` 在 `!provider.ready` 时 return 居中 `CircularProgressIndicator`（zen/paper 配色，用 `PaperPalette` 系颜色），ready 后渲染原内容。
   - 只加「早退分支」，不改原渲染逻辑。

### 边界

- 只动 calendar demo；不动 clock/recorder 等其它 demo。
- 不新增 package；loading 用 Flutter 自带 `CircularProgressIndicator`。
- 不做预热（用户明确选 B，不选 A）。

### 验收

- 单测：`LabCalendarProvider.ready` 初始 false（构造后同帧）；`LabPeopleProvider.ready` 同理（若 provider 构造在测试环境可跑；Hive 依赖若阻塞则退化为纯标志位单测）。
- 真机：进入日历 → 短暂 loading 圈（无空网格闪现）→ 数据完整呈现；不再有「先空后满」的组件闪烁。
- flutter analyze 干净。

## 簇 C — 课表学校模式去掉重复入口（任务 #3）

### 现状（已读码确认）

上一轮（B 簇）只改了**通用模式**（`_buildGeneralDateField`，单一日期入口，无周一对齐）。**学校模式 `_buildSchoolDateField`（`timetable_settings_page.dart:355-434`）保留了两个入口**：
- **入口 A（第 359-394 行）**：卡片 `InkWell` → `WeekCalculatorDialog`（内含「周数推算」+「选日期」两个 Tab，选完自动回退周一）
- **入口 B（第 397-432 行）**：独立 `OutlinedButton`「选日期（自动对齐到最近周一）」→ 直接 `showDatePicker` → `findNearestMondayOnOrBefore` 回退周一

两者本质重复（都是「选日期 → 对齐周一」），B 是 A 的 Tab2 的快捷版 = 用户说的「通过日期自动对齐周一，有两个入口，重复了」。

### 目标（用户拍板：删独立按钮，留卡片）

删掉入口 B（独立 OutlinedButton），只留卡片入口 A。功能不丢——`WeekCalculatorDialog` 内已有「选日期」Tab 覆盖同一需求，且还带「周数推算」能力。

### 修法

`timetable_settings_page.dart`：删除 `_buildSchoolDateField` 内第 395-432 行区域的 `const SizedBox(height: 8)` + 整个 `SizedBox(height: 40, child: OutlinedButton.icon(...))` 块。删后检查 `findNearestMondayOnOrBefore` 是否仍被引用（`_save` 经 `resolveStartDateIso` 间接用、`WeekCalculatorDialog` 内用）→ 若本文件不再直接引用则不必删 import（`resolveStartDateIso` 同文件导出）；以 analyze 结果为准，避免 unused_import 告警。

### 验收

- 真机：课表设置页切学校模式 → 起始日期区**只有一个卡片入口**，点卡片仍能走「周数推算」/「选日期（自动对齐周一）」两个 Tab；通用模式行为不变（单一日期选择、不回退周一）。
- flutter analyze 干净（无 unused_import / unused_element 新增）。
