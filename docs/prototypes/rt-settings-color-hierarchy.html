Visual Hierarchy · color layering

RT 设置页 · 色彩层次提案

问题很具体：布局大卡和页面底色是同一个白，整页只剩「1px 描边」在支撑层次。参照系是 app 自己的设置页——它用灰底 + 白卡 + 蓝色强调做三层。下面三个方案的区别只在「层次从哪来」：明度、色相、还是点缀。

现状 页底 surface = 卡面 surface 参照 app 设置页 surfaceContainerHighest + surface 约束 暗黑主题无彩色系 → 层次不能只靠色相 日期 2026-10-23
01

诊断：层次断在哪一层

把设置页的视觉元素按「应该处于哪一层」摊开，问题立刻可见。

视觉元素期望层级现状结果
页面底画布层（最暗/最灰）cs.surface = #FFFFFF底与卡同色，卡片「浮不起来」
布局大卡卡片层（白）cs.surface = #FFFFFF与底同色，只剩 1px outlineVariant 描边
组头（竖屏/横屏）卡内凹槽（灰）无底色，只有文字两个朝向没有视觉分界
激活行强调层（主题色）仅文字变 primary扫读时「谁在用」不跳出来
输入 / 其他行卡片层（白）裸 ListTile 直接躺在白底上与布局区同级，偏好项没有归组
新建虚线行卡片层（白 + 虚线）白底 + 虚线，浮在白页上虚线看得见，卡片感缺失
根因一句话：app 设置页用「页底灰、卡面白、强调蓝」三层明度配方；RT 设置页只抄了「卡片是白」，没抄「底是灰」，于是三层塌成一层。
初稿修正（你指出的问题）：组头条原先用与页底完全相同的灰、且顶着卡片圆角边——条带直接融进页面底色，像卡片开了个洞。v2 改为卡内悬浮圆角凹槽：条带四周留 8px 白边（卡面在凹槽与页底之间形成隔离带）+ 圆角 10 + 1px 细线勾边。颜色仍是 surfaceContainerHighest，但「悬浮 + 勾边」让它读作卡上的一层凹槽，而非页底的延伸。
02

参照系：app 设置页的真实配方

左边是 app 设置页实拍（渲染自真实代码），右边是 RT 设置页现状——两张放一起，差别就是「底色」。

app 设置页还有两个可直接借用的手法：① 钉选格子的图标放进 primaryContainer 圆角方井（浅蓝块 + 深蓝图标）——不需要新色，主题自带；② 通用项收进一张白卡（_GeneralCard），页面上不再有裸行。

B

色相分层

在 A 之上再给朝向染色：竖屏组 = primaryContainer，横屏组 = tertiaryContainer，激活行跟着所属组染色。两个朝向一眼可分。

C

点缀分层

灰底白卡不变，主题色只花在激活处（图标井、自定义徽标）；分组退成纯文字标题——无底色、无分隔带，组间靠标题与留白呼吸。最素的一版。

04

暗色验证：暗黑主题下的 A

暗黑主题是无彩色系（primary 是暖灰 #C9C5BD），色相分层在这里直接失效；明度分层依然成立——这是选 A 的主要理由。
