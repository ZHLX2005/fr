## Ec — 组件分层与复用治理

> Ec 是**扁平子序列**（无自己的 `00` 路由文件），成员直接由 E00 登记。
> 覆盖范围：整个共享组件层 —— `lib/core/ui/`（atomic / shell / zen / lab / renderers / global_ring / **game**）与 `lib/core/game_kit/`（纯逻辑：spec / slots / identity / skin / 脚本）。Ea 只管**视觉模式**，Eb 只管**颜色与主题通道**，**组件资产本身的分层、复用与健康度归 Ec**。

## 全局红线

- `lib/` 新增 UI 禁止裸写 `Color(0xFF...)`；使用 Theme/ColorScheme 或项目颜色 strategy。
- 先判断功能型/内容型，再选样式或颜色策略；不要把组件配方与主题 token 架构混为一谈。
- **复用优先于新建**：写 UI 前先查已有组件；已有件漏用先改用，确无同形态件才新建。判定与分层契约见 Ec 子序列。
- FR 具体主题与策略以当前代码为准。旧文档中的版本、数量若与实现不同，按真实代码校准。
