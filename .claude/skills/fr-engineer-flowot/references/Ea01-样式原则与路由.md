# Ea01 — FR UI 样式原则

> 适用范围：仅适用于 FR 项目。E00 是 E 大序列总路由；样式方案分类见 [[Ea02-样式分类路由]]。FR 原型事实源位于 `docs/prototypes/`，原型映射入口见 [[Ea13-原型对齐路由]]。

## 何时使用

- 做 UI 样式选型、视觉对齐或 Material 3 组件样式决策。
- 将“看起来像 demo”的内容目录改造成有层级的商店式列表。
- 选择 Banner、Card、Button、NavigationBar、Modal、浮卡、托盘分段或大厅就绪模式。
- 根据 HTML 原型、Figma 或截图确定 Flutter 方案。

主题 token、`ColorStrategy`、`ThemeExtension` 架构由 E00 路由至 Eb 子序列，见 [[Eb01-主题系统简述]]。

## 核心原则

### 先判页面性质：功能型 vs 内容型

**相同的颜色/权重规则，在功能页与内容页上的结论可能相反；先判断条目代表操作还是作品。**

| 页面性质 | 条目是什么 | 视觉策略 |
|---|---|---|
| **功能型**：工具、表单、设置、密集按钮区 | 操作 | 减负：统一主题色与边框强调；避免大量独立描边和装饰色。见 [[Ea03-边框强调式减负]]、[[Ea08-Zen浮卡少描边]]。 |
| **内容型**：游戏中心、媒体库、作品集、模板市场 | 作品 | 给内容身份：专属封面/渐变、层级明确的列表与精选位；游戏表面遵守 [[Ea14-游戏表面ColorScheme契约]]。 |

把内容型目录按功能型方式处理（统一占位 icon、所有卡片一律无填充描边）会让页面保持“demo”形态；不能把“减少纯色填充”当作全局禁令。

### 视觉权重：该减负时减，不该减时保留识别

- 密集操作区：用清晰的 border-emphasis 或克制填充分组，避免描边噪音。
- 封面、Hero、仪式感 CTA：可以使用必要的色彩、填充和识别度；用页面内容目标判断。
- 导航/功能入口、操作按钮、内容条目是不同角色，不能套一条颜色规则；具体主题色消费见 Eb 子序列。

### 异步 UI 状态必须完整

嵌套 Sheet 异步加载不能 fire-and-forget；先有明确 loading/error 状态，再接数据结果，防止关闭/重开竞争。案例见 [[Ea12-嵌套sheet异步加载防race]]。

## 常见视觉反模式

- 导航/功能入口 icon 使用彩虹色，但内容目录反而统一占位图。
- 所有操作按钮都用同一个主题色，忽略主操作、查询、停止、危险操作语义。
- 内容型页面套用“工具表格”密度，缺少封面、留白和内容识别。
- 将浅 surface 直接接到深色 banner，造成头部视觉断层。
- 使用 `withOpacity`（优先采用当前 Flutter API `withValues(alpha:)`）。
- 破坏性操作失去警示色语义。
- 嵌套 Sheet 以 fire-and-forget 方式异步加载。
- 工具页一律套用全胶囊 chrome；应结合页面性质与原型判断。
- 游戏表面硬编码 Zen 专属 hex，忽视不同 ColorScheme 的对比关系。
