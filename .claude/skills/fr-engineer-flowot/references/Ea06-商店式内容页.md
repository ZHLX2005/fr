# Store-Style Content Page（商店式内容页）

> 分类：样式大类 = **内容列表页 / Content Index**，子类 = **Store-Style Content Page**。
>
> 何时读：做游戏中心 / 媒体库 / 作品集 / 插件市场这类**内容型**列表页，或要把"一堆长得一样的占位卡"改成有识别度的商店形态时。
>
> 落地代码：`lib/screens/profile/lab/game_center_page.dart` + `game_center/`（const / artwork / cards 三件套）。
>
> ⚠️ 头部方案已改版：现在**没有**渐变头部、**没有** AppBar 收拢——见 Step 4。
>
> 全主题对照原型：`docs/prototypes/game-surfaces-palettes.html`——布局抄本 ref，**颜色契约**抄 [[Ea14-游戏表面ColorScheme契约]]（禁写死 Zen sage/clay）。

**核心判断**：内容型页面 ≠ 功能型页面。功能型（工具、表单、密集按钮区）要**减负**（见 [[Ea03-边框强调式减负]]）；内容型要**给每条内容视觉身份**。没有身份 = demo 感。

---

## 一、实现思路

### Step 0 · 先定性：这页是内容型还是功能型

| 页面性质 | 判据 | 配色策略 |
|---|---|---|
| 功能型 | 条目是"操作"（按钮、开关、设置项） | 统一主题色 + border-emphasis 减负 |
| 内容型 | 条目是"作品"（游戏、文章、媒体、模板） | **每条内容专属色**，靠封面建立层次 |

判错方向，后面全白做。

### Step 1 · 视觉身份登记表（const_xxx.dart）

把每条内容的身份收进一张**以稳定 ASCII key（slug）为索引**的常量表，UI 只读表、不写死：

```dart
class GameMeta {
  const GameMeta({
    required this.categories,   // 多归属：Set，不是单个 String
    required this.icon,
    required this.gradient,     // 专属渐变（两色）
    required this.mode,         // 玩法/类型短标签："联机双人"
    this.pattern = GameArtPattern.blob,
  });
  bool get isOnline => categories.contains(GameCategory.multiplayer);
}

const Map<String, GameMeta> kGameMeta = {
  'gomoku-lua': GameMeta(
    categories: {GameCategory.multiplayer, GameCategory.board},
    icon: Icons.grid_4x4_rounded,
    gradient: [Color(0xFF0F766E), Color(0xFF14B8A6)],
    mode: '联机双人',
    pattern: GameArtPattern.grid,
  ),
  // ...
};

GameMeta gameMetaOf(String slug) => kGameMeta[slug] ?? kFallbackGameMeta;
```

要点：
- **按 slug 不按 `is XxxDemo`**：常量层零依赖实现文件，增删内容不牵动 import 图。
- **必须有 fallback**：忘登记的新条目不白板、不崩。
- **分类用 Set 多归属**：`联机五子棋` 同时进「联机」和「棋游」，单归属放不下。

### Step 2 · 程序化封面（没有美术资源也不能长得一样）

三层叠加，顺序固定：

```
① 专属渐变底（LinearGradient topLeft→bottomRight）
② CustomPainter 装饰图案（blob / stripes / grid / dots / wave，白色 alpha 0.07~0.16）
③ 主图标居中（白色 alpha 0.92）
```

> **压暗蒙版整层已于 2026-09-22 移除**（`lib/screens/profile/lab/game_center/game_center_artwork.dart:8-9` 注释：「移除整层压暗蒙版，封面保持原色」）。当前代码里**没有**这一层，不要照着写。

用户设过自定义图（`backgroundPath`）或走皮肤管线的远程封面（`remoteCover`）时，用图替换 ①②；此时封面的可读性由**精选卡底部信息条的浅渐变托底**兜底（`game_center_cards.dart:99-106`，渐变强度 2026-09-22 从 0.62 降到 0.32），不再靠封面自己压暗。

### Step 3 · 收藏轮播（PageView）

> 语义已漂移：这一区块早期叫「顶部横向精选」（按"联机"硬编码），现在是**「我的收藏」**——数据源是玩家收藏的游戏，不是推荐位。改文案时注意别再叫"精选"。

```dart
final _featuredController = PageController(viewportFraction: 0.88);   // 露出下一张的边，暗示可横滑
```

数据源（`game_center_page.dart:230-240`）：

```dart
/// 轮播数据源：收藏的游戏（按 Lab 面板的收藏顺序），不再按"联机"硬编码。
List<DemoPage> get _featured {
  final order = _provider.getFavoritesOrder();
  final list = _games.where((d) => _provider.isFavorite(d.title)).toList();
  list.sort((a, b) => order.indexOf(a.title).compareTo(order.indexOf(b.title)));
  return list;
}
```

区块标题为「我的收藏」（`:336`），副标题是「N 款 · 点星标管理」；收藏为空时渲染 `_EmptyFeatured` 空态引导而不是空白。轮播只在"全部"筛选下出现，切到具体分类就收起——否则同一条内容上下重复两次。

### Step 4 · 搜索框即头（H3R-C）+ 滚动后毛玻璃细条

> **这一节的旧设计（Hero 头部收拢成 AppBar、同源渐变）已废弃**。文件头注释写得很明确（`game_center_page.dart:4`）：「① 顶部功能行：返回键 + 描边搜索框（H3R-C「搜索框即头」，**无标题无渐变**）」。当前实现里没有渐变头部、没有 AppBar。

现状三件事：

**① 底色跟壳层**：`backgroundColor: scheme.surfaceContainerLowest`（`game_center_page.dart:319`），五主题（含暮紫 dark）自动切换。

**② 头部就是一个描边搜索框**（`:404-420` `_buildHeader`）：返回热区内嵌在搜索框左端，整行只有一根胶囊——返回键与搜索框不再并列。高 `kGcTopRowHeight` = 44，上边距在有状态栏 inset 时取 `inset + 12`、无 inset（桌面/横屏）取固定 16，下边距 12。

**③ 滚动越过阈值后淡入一条毛玻璃细条**（`:505-525` `_buildGlassBar`）：`BackdropFilter` blur 14 + `surface @ 0.82` + 底部 `outlineVariant @ 0.7` 描边，内含返回箭头 + 标题 + 搜索/历史 mini 图标。淡入进度 = `scrollController.offset / kGcGlassBarThreshold`（`:162`），未完全显现时 `IgnorePointer` 避免抢手势。

这样就避开了旧设计要解决的核心问题：**不需要"头部滑走、AppBar 补色"的色系对撞**，因为压根没有第二个头部。

### Step 5 · 自适应网格

```dart
SliverGridDelegateWithMaxCrossAxisExtent(
  maxCrossAxisExtent: 210, childAspectRatio: 0.80,
  mainAxisSpacing: 14, crossAxisSpacing: 14,
)
```
用 MaxCrossAxisExtent 不用 crossAxisCount：手机 2 列、平板/折叠屏自动 3~4 列，零分支。

### 验收 checklist

- [ ] 每条内容的封面彼此可辨（不是同一个占位 icon）
- [ ] 顶部只有搜索框一根胶囊，没有标题、没有渐变头部
- [ ] 滚动越过阈值后毛玻璃细条淡入，图标可点
- [ ] 收藏轮播横滑露出下一张的边
- [ ] 平板宽度下网格自动增列，不出现超宽卡
- [ ] 分类 chip 数量与实际分桶一致（含收藏实时刷新）

## 二、踩坑总结

### 坑 1 · 头部做成"渐变 banner + AppBar 收拢"→ 色系对撞 + 头部喧宾夺主

**现象**：下滑过程中深色头部滑走、浅色 AppBar 淡入，交界处色系对撞；头部占掉近半屏，统计胶囊比游戏卡还抢眼。

**根因**：把头部和 AppBar 当"两个组件"分别配色，而不是"同一片区域的两种呈现"；再叠加头部信息过载（标题 + 大统计胶囊）。

**结论（现行做法）**：砍掉渐变头部与 AppBar，改成**搜索框即头**——头部只有一根 44 高的描边搜索胶囊；滚动后的导航需求由**毛玻璃细条**承担（淡入而非换色）。统计概览全部删除。

### 坑 2 · 想复用旧渐变头部代码 → 找不到 `_headerGradient`

**现象**：照着旧文档实现会去找 `_headerGradient()` / `_titleReveal`，但当前 `game_center_page.dart` 里**没有**这两个符号。

**根因**：H3R-C 改版时整段头部逻辑被删除，不是重构改名。

**结论**：以当前文件为准——头部 = `_buildHeader()`（搜索框），滚动提示 = `_buildGlassBar()`（毛玻璃细条），渐变头部已不存在。

### 坑 3 · 卡片覆盖层压暗蒙版照抄旧文档 → 多一层不存在的层

**现象**：照旧文档给封面加"压暗蒙版"，与现有代码重复且与精选卡底部信息条渐变叠加过暗。

**根因**：压暗蒙版整层已于 2026-09-22 移除（`game_center_artwork.dart:8-9`）。

**结论**：封面只有 渐变底 + 装饰图案 + 主图标 三层；可读性靠精选卡底部信息条渐变兜底。

### 坑 4 · 收藏轮播按"精选"命名 → 语义与实现脱节

**现象**：文案写"精选"，数据源却是玩家收藏；后续接手的人以为要接推荐位。

**根因**：区块从"按联机硬编码的精选"改成"收藏顺序"后，文案没跟着改。

**结论**：统一叫「我的收藏」，数据源是 `_provider.getFavoritesOrder()` + `isFavorite(title)`（`game_center_page.dart:230-240`）。

### 坑 5 · 统一分类占位 icon = demo 感的根源

**现象**：9 张卡用同一个 `Icons.sports_esports` 占位，列表像未完成的脚手架。

**结论**：没有美术资源不是借口。渐变 + 图案 + 图标三件套足以生成可辨识封面（Step 2）。**"看起来像 demo"绝大多数时候是内容缺少视觉身份，不是布局不够花哨。**

### 坑 6 · 别名 slug 导致同一条内容渲染多张卡

**根因**：注册表允许一个实例挂多个 slug（历史兼容 / 别名路由），`getAll()` 返回全部条目。

**结论**：UI 渲染前按**实例**去重（`where(seen.add)`），路由查询才用全量。

### 坑 7 · 分类单归属放不下跨类内容

**现象**：`联机五子棋` 放「联机」就不在「棋游」里，放「棋游」用户在「联机」找不到。

**结论**：`categories` 用 `Set<String>`，一条内容可进多个桶；"本地版"与"联机版"靠是否含 `multiplayer` 区分，而不是靠两个互斥分类。
