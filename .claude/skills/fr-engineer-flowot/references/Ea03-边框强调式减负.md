# Ea03 — 边框强调式减负

> 何时读：改造纯色填充按钮/icon 容器 / 减负密集按钮区 / 判断「左重右轻」时。
>
> 组件化提示：本配方**已有共享实现**（`lib/core/ui/shell/emphasis_button.dart` 的 `EmphasisButton`），详见下方「已有共享实现」一节——**先查共享件，不要再手写 `_outlinedBtnStyle` helper**。判定规则见 [[Ec01-组件分层与复用契约]]。

---

## 一、适用边界（先读）

本方案只适用于**功能型**界面——工具页、表单、设置、密集操作按钮区。
**内容型**页面（游戏中心 / 媒体库 / 作品集）反向操作：封面、Hero 头部、主 CTA 该填充就填充，每条内容还要有专属识别色，见 [[Ea06-商店式内容页]]。
把本方案当全局禁令套上去，结果就是所有卡片长一样的「demo 形态」。

## 二、已有共享实现（先查这里）

| 档位 | 共享 API | 位置 | 说明 |
|---|---|---|---|
| 一般功能 | `EmphasisButton.borderEmphasis(context, color:)` | `lib/core/ui/shell/emphasis_button.dart:36` | 浅 tint 底 + 同色描边 + 同色前景 |
| 破坏性操作 | `EmphasisButton.dangerEmphasis(context)` | 同上 `:57` | 红由 `colorScheme.error` 派生 |
| 次要辅助 | `EmphasisButton.ghostEmphasis(context, color:)` | 同上 `:63` | 透底，仅文字色，无描边 |

**这些是 `ButtonStyle` 工厂**，调用方自己组装 `OutlinedButton`：

```dart
OutlinedButton(
  style: EmphasisButton.borderEmphasis(context, color: colorScheme.primary),
  onPressed: _download,
  child: const Text('下载'),
)
```

- 圆角取自 `Theme.of(context).cardTheme.shape`（`emphasis_button.dart:24-31`，实际落到 `AppRadius.xl=16`），不是 `AppRadius.xs`。
- tint 底 alpha：暗色 0.18 / 亮色 0.08；描边 alpha：暗色 0.65 / 亮色 0.5。
- 全仓 **84 处**调用，**不要再造第三个 helper**。

> ⚠️ 语义色（green/blue/orange/red）目前仍散在各调用点（`Colors.blue` / `Colors.red`），尚未收进常量组；需要跨页一致时优先用 `EmphasisButton` 的参数传色，不要复制 tint/描边数值。

## 三、核心配方（三件套）

浅色 tint 背景 + 同色描边 + 同色前景。经验 alpha：

| 部位 | alpha | 说明 |
| --- | --- | --- |
| tint 背景 | 0.08 ~ 0.12 | 给轮廓一点「存在感」，又不抢眼 |
| 描边 | 0.30 ~ 0.50（width 1.5） | 主视觉信号 |
| 前景（icon/text） | color 本色 | 与描边同色，整体协调 |

### Icon 容器模板

```dart
final accent = Theme.of(context).colorScheme.primary; // 或功能色

Container(
  width: 52,
  height: 52,
  decoration: BoxDecoration(
    color: accent.withValues(alpha: 0.10),
    borderRadius: BorderRadius.circular(12),
    border: Border.all(color: accent.withValues(alpha: 0.35), width: 1.5),
  ),
  child: Icon(icon, color: accent, size: 24),
)
```

### 语义色决策：装饰性 vs 功能性（最易错，必读）

**规则相反，不能一刀切。** 这是本序列最核心、最易翻车的判断：

| 元素类型 | 配色策略 | 例子 |
| --- | --- | --- |
| **导航 / 功能入口**（菜单卡 icon、tab、纯装饰） | **统一主题色** `Theme.of(context).colorScheme.primary` | profile 菜单卡片 |
| **功能性**（操作按钮） | **撞色编码语义** | APK / KV / 文件 tab 按钮 |
| **内容条目**（游戏、媒体、作品、模板） | **每条专属识别色**，集中登记在 `const_xxx.dart` 的 slug 表 | 游戏中心卡片封面 → [[Ea06-商店式内容页]] |

功能性语义色对照表（跨页面保持一致）：

| 色 | 语义 | 典型按钮 |
| --- | --- | --- |
| green | 主操作 / 成功 / 写入 | 安装、上传、设置 |
| blue | 查询 / 接收 / 读取 | 检查更新、下载、获取 |
| orange | 暂停 / 警示 | 暂停、停止 |
| **red** | **危险 / 删除** | 取消、删除（**永远保留红**） |
| indigo / teal / deepPurple | 差异化 / 备用操作 | 浏览器下载、继续下载、媒体播放 |

> 注意区分：上表是**功能语义色**，应随主题走；**识别色锁定**（棋盘色等不随主题变化的色）属 [[Eb05-颜色特例策略]]，两者不是一回事。

## 四、错误案例（高频坑点）

| 错误操作 | 实际后果 | 正确做法 |
| --- | --- | --- |
| 给**导航/功能入口**配彩虹独立色 | 显幼稚、违和、不统一 | 导航 icon 用统一主题色（**内容条目不适用**：作品卡就该有专属色） |
| 给**操作按钮**统一主题色 | 功能无区分、层级丢失 | 按钮用撞色编码语义 |
| 用`.withOpacity(x)` | analyze 报`deprecated_member_use` | 用`.withValues(alpha: x)` |
| 删除/取消按钮也去掉红色 | 危险操作失去警示语义 | 破坏性操作**永远保留 red** |
| 改了按钮忘同步 spinner 颜色 | loading 圈与描边撞色不协调 | `CircularProgressIndicator(color: 同按钮色)` |
| 在**同一片密集按钮区**里留个别纯色填充 CTA | 用户仍投诉「还有纯色」 | 该区域内全转 OutlinedButton；层级靠**颜色 + 位置**。⚠️ 仅限本区域——不要外推到内容页封面 / Hero 头部 |
| helper 第一版写成`(BuildContext, {bool destructive})` | 只能二选一，无法表达多语义色 | 直接收`Color` 参数；或直接用 `EmphasisButton.borderEmphasis(context, color:)` |
| 改造范围蔓延到`IconButton`（纯图标） | 误伤，IconButton 本就不算纯色块 | 只改「填充式」容器/按钮 |
| **手写 `_outlinedBtnStyle` helper** | 与 `EmphasisButton` 形成第二套 tint/描边数值，逐渐分叉 | 用 `EmphasisButton`；确需自定义 alpha 时在其基础上改 |

## 五、检查清单

- [ ] 无残留 `LinearGradient` / 饱和 `color` 填充的 icon 容器
- [ ] 无残留 `ElevatedButton(backgroundColor: Colors.X, foregroundColor: white)` / `FilledButton(backgroundColor: Colors.X)`
- [ ] 装饰元素统一主题色，功能按钮撞色
- [ ] 破坏性操作保留红色
- [ ] 全用 `withValues(alpha:)`，无 `withOpacity`
- [ ] **按钮样式来自 `EmphasisButton`，不是本地 helper**
- [ ] loading / spinner 颜色与所在按钮同步
