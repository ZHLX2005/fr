## 三、pre-flight 六步（写 UI 前 30 秒）

1. **查组件**：有没有现成的？——《Eb01 组件能力目录》§1。有则改用，**不要新建**。
2. **定色通道**：这个颜色的语义是什么？——《Ea01 主题与token地图》§1。禁止裸写 `Color(0x…)`。
3. **定几何档位**：圆角/间距只取 token 档位——《Ea02 token 字典》§1–§2。
4. **定落点**：新组件放哪层、叫什么、怎么建 `main.dart`——《Eb02 分层契约与放置》§2。
5. **参数化**：颜色走 strategy / ColorScheme；默认文案中文本地化；透明度用 `withValues(alpha:)`。
6. **验证**：`flutter analyze` + 相关测试；涉及原生改动另跑 `flutter build apk`。

## 四、全局红线

- `lib/` 新增 UI 禁止裸写 `Color(0xFF…)`；使用 Theme/ColorScheme 或项目 ColorStrategy。豁免必须走《Ec03 特例豁免》登记。
- 复用优先于新建：已有件漏用优先改用；确无同形态件才新建，且必须带真实调用点。
- 通用件不得定义在业务模块内；逻辑层不得 import `core/ui/`。
- 字号走 semantic TextTheme；不在 widget 里发明新的圆角/间距档位。
- 不使用 `withOpacity`（用 `withValues(alpha:)`）。
- 组件默认文案必须本地化（中文），具体动作词由调用方传参。
- 文档里的数字（主题数、角色数、审计计数）以当前源码为准；数字滞后时先核实代码再改文档。

## 七、维护规则

- **单层路由**：成员登记只在本表；册与册之间不建 wikilink，需要引用时写纯文本《册名 §章节》。每个册只在页首回指本表一次（星型拓扑）。
- **字母含义**：Ea 主题与 token 骨架 / Eb 组件骨架 / Ec 骨架变更动作 / Ed 视觉配方（兜底）。新增册按此归位。
- **编号**：每个字母层内从 01 顺序编号；已删除的编号不再复用。
- **拆分依据**：单册超过 ~400 行或承担两种职责时拆分；配方类保持一份一配方，不合并。
- **治理史不进 skill**：落地记录、审计快照、阶段史一律归档到 `docs/architecture/` 与 `plan/`，册内只留指针。
