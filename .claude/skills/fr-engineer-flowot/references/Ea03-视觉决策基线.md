# Ea03 — 视觉决策基线

> 骨架层 · 视觉判断。索引见 [[E00-UI骨架地图]]；取色通道见《Ea01 主题与token地图》；具体配方在 Ed 案例层。
> 本文件是**判断基线**，不是配方库：它回答「按什么标准判断」，配方册回答「具体怎么做」。

## 1. 先判页面性质：功能型 vs 内容型

**相同的颜色/权重规则，在功能页与内容页上的结论可能相反；先判断条目代表操作还是作品。**

| 页面性质 | 条目是什么 | 视觉策略 |
|---|---|---|
| **功能型**：工具、表单、设置、密集按钮区 | 操作 | 减负：统一主题色与边框强调；避免大量独立描边和装饰色。见《Ed01 边框强调式减负》《Ed05 Zen浮卡少描边》。 |
| **内容型**：游戏中心、媒体库、作品集、模板市场 | 作品 | 给内容身份：专属封面/渐变、层级明确的列表与精选位；游戏表面遵守 §3 的 ColorScheme 契约。 |

把内容型目录按功能型方式处理（统一占位 icon、所有卡片一律无填充描边）会让页面保持「demo」形态；不能把「减少纯色填充」当作全局禁令。

## 2. 视觉权重：该减负时减，不该减时保留识别

- 密集操作区：用清晰的 border-emphasis 或克制填充分组，避免描边噪音。
- 封面、Hero、仪式感 CTA：可以使用必要的色彩、填充和识别度；用页面内容目标判断。
- 导航/功能入口、操作按钮、内容条目是不同角色，不能套一条颜色规则。

## 3. 游戏表面 ColorScheme 契约

> 适用：改游戏中心 / 房间就绪 / 大厅入口，且要跟 `AppThemeMode` 七主题切换；或对照 `docs/prototypes/game-surfaces-palettes.html`。

**通用消费通道**：普通/棋盘/象棋/俄罗斯方块/团队头像走 `context.colors / boardColors / chessColors / tetrisColors / teamAvatar`；数独走 `context.sudokuColors`（其 ThemeExtension 尚未注入 app_theme，读数走 factory fallback）。护眼通道当前无 context 入口（见《Ea01 主题与token地图》§6）。

### 3.1 必须 / 禁止

| 必须 | 禁止 |
|---|---|
| 铬件颜色只来自 `Theme.of(context).colorScheme` / `context.colors` | 在游戏表面硬编码 sage `#7A9A7E` / clay `#A0594A` |
| CTA 文字用 `onPrimary` / `onTertiary` | 假定 `onPrimary == white`（lemon/purple 为深色字） |
| 收藏 / 警告点缀走 `tertiary` | 把 lemon 的绿味 tertiary 当主 CTA 底 |
| 封面渐变用主题 cover token 或 slug 识别色表 | 全主题共用一套写死的深绿封面 |

### 3.2 角色速查（与原型 CSS 变量对齐）

| 用途 | Scheme |
|---|---|
| 主按钮底 | `primary` |
| 主按钮字 | `onPrimary` |
| 图标瓦 / chip.on 底 | `primaryContainer` |
| 图标瓦字 | `onPrimaryContainer` |
| 收藏、就绪描边、稀有强调 | `tertiary` / `onTertiary` |
| 卡面 | `surface` |
| 托盘 / 凹陷井 | `surfaceContainerHighest` |
| 弱字 | `onSurfaceVariant` |
| 分割 | `outline` |

### 3.3 三块表面同一契约

原型把同一套变量套在：① **游戏中心**（featured + 网格封面，布局见《Ed04 商店式内容页》）；② **房间就绪**（code pill / seats / stacked CTA，见《Ed08 大厅与房间就绪》）；③ **大厅入口**（mark + form + 胶囊 CTA）。

换 `data-palette` / `AppThemeMode` 只换 scheme，**不换布局几何**。

### 3.4 自检清单（改完必过）

- [ ] 切 purple/lemon 后主按钮字仍可读（用了 onPrimary）
- [ ] 无 `Color(0xFF…)` 出现在本次改动的游戏 UI（豁免须注释并按《Ec03 特例豁免》登记）
- [ ] fav 不是 primary 实心大块
- [ ] Zen 默认观感仍对，但不依赖写死 Zen hex

### 3.5 踩坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 从 Zen 原型抄 hex 进 Dart | 切主题失效 / 审计不过 | 只抄「用了哪个角色」 |
| 徽章/eyebrow 用 onPrimary 却铺在 surface | 对比度错 | 分清底角色再选 on* |
| 商店封面不跟主题 | purple 夜间仍是茶禅绿坡 | cover 梯度随 palette 或 slug×scheme 调 |

## 4. 常见视觉反模式

- 导航/功能入口 icon 使用彩虹色，但内容目录反而统一占位图。
- 所有操作按钮都用同一个主题色，忽略主操作、查询、停止、危险操作语义。
- 内容型页面套用「工具表格」密度，缺少封面、留白和内容识别。
- 将浅 surface 直接接到深色 banner，造成头部视觉断层。
- 使用 `withOpacity`（用 `withValues(alpha:)`）。
- 破坏性操作失去警示色语义。
- 嵌套 Sheet 以 fire-and-forget 方式异步加载（→《Ed09 嵌套sheet异步加载防race》）。
- 工具页一律套用全胶囊 chrome；应结合页面性质与原型判断。
- 游戏表面硬编码 Zen 专属 hex，忽视不同 ColorScheme 的对比关系。
