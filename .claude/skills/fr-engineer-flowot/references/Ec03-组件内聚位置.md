## 2. 周边层次的位置（非 ui/ 但同属体系）

| 层 | 位置 | 内容 |
|---|---|---|
| L1 token | `lib/design_tokens/` | `radius.dart` / `spacing.dart` / `typography.dart` / `color/`（palettes ×7、app_colors_extension、tetris 等）——字典见 [[Eb06-token变量定义]] |
| L2/L3 主题 | `lib/core/theme/` | `app_theme.dart` 装配、`state/theme_provider.dart`、`colors/strategy/`（7 套契约+default）、`extensions/`（7 个注入器）、`context/`（6 个消费入口）、`text_theme.dart` |
| 联机逻辑 | `lib/core/game_kit/` | **只剩纯逻辑**：`lobby/`（spec + slots + identity ×2）、`chat/`（chat_event / chat_script / barrel）、`emoji/`（bundle / pack_meta / script / snapshot / assembler / barrel）、`skin/`（10 文件）、`game_center_catalog.dart`。UI 一律不放这里 |
| 业务模块 | `lib/core/<模块>/`、`lib/lab/demos/<模块>/` | 模块专属 UI；**不得定义跨模块通用件** |

## 3. 放组件的速查（新组件三问）

```text
① 换个模块还要用吗？
   ├─ 否 → 留在业务模块内（私有 _ 前缀）——这是正确做法，不要下沉
   └─ 是 → ②
② 是联机域的吗？
   ├─ 是 → 是 UI 件 → lib/core/ui/game/；是逻辑（spec/协议/脚本/模型）→ lib/core/game_kit/
   └─ 否 → ③
③ 有业务语义的组合件，还是无语义原子件？
   ├─ 应用级 chrome / 全局风格（zen）→ lib/core/ui/shell/ 或 zen/
   └─ 无业务语义单一形态 → lib/core/ui/atomic/（Base* 命名，必须带真实调用点）
```

依赖方向硬约束：`atomic → theme/token`；`shell/zen/game → atomic + game_kit(逻辑)`；`业务模块 → 以上全部`。**逻辑层不得 import UI**（`game_kit/` 与 `net_engine/` 中的 `.dart` 不得出现 `core/ui/` import）。
