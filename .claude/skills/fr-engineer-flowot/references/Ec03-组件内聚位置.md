# Ec03 — 组件内聚位置

> 适用范围：仅 FR 项目。本文件是**位置地图**（查询用）：什么组件住在哪、新组件放哪。判定契约（何时抽/何时改用）见 [[Ec01-组件分层与复用契约]]；现状热点与收敛路线见 [[Ec02-组件现状与收敛路线]]。基线 2026-10-28（职责清晰重构后）；文件增删后以目录实况为准。
> 进度与决策记录：`plan/ui-convergence-2026-10-28.md`（首轮 + 细粒度 9 轮 R1–R7 + 职责清晰 9 轮 N1–N9）。

## 0. 目录规范（2026-10-28 用户裁决，硬约束）

```text
lib/core/ui/global/<类别>/main.dart   # 全局件：被 ≥2 个域消费才允许放这里
lib/core/ui/<域>/<类别>/main.dart     # 专类件：只服务一个域时归该域，如 ui/game/entry/main.dart
lib/core/ui/lab/<demo>/<类别>/main.dart  # lab demo 域
lib/core/utils/<类别>/main.dart        # 工具函数（镜像同粒度）
```

- **main.dart 是类别唯一入口**；类别总行数 ≤ ~400 行时 main.dart 直接装全部代码，超出时 main.dart 做 barrel、实现文件同目录并列（私有 `_` 前缀文件不 export）。
- `ui/global_ring/`（特性级悬浮环）与非组件文件不受类别规范约束，原位保留。
- 判定口径：只看**消费域集合**。≥2 域 → global；单域 → 该域。归类有疑问时先查本文 §5，再查 `plan/` 进度文件里的盘点表。

## 3. 放组件的速查（新组件三问）

```text
① 会被 ≥2 个业务域消费吗？
   ├─ 否 → 留在本域：lib/core/ui/<域>/<类别>/main.dart（如 ui/game/entry/main.dart）
   └─ 是 → lib/core/ui/global/<类别>/main.dart
② 类别归谁：按形态归（button/nav/dialog/dot/section/empty_state/notification/renderers/zen/chat/...）；
   新形态才建新类别目录，且一个类别只做一种职责。
③ 只是本模块私有的小部件？
   └─ 留在业务模块内（私有 _ 前缀）——这是正确做法，不要下沉。
```

依赖方向硬约束：`global/<cat> → theme/token`；`ui/<域>/<cat> → global/* + game_kit(逻辑) + net_engine`；业务模块 → 以上全部。**逻辑层（game_kit/net_engine/net_p2p/message_net/theme/storage）不得 import `core/ui/`**（页面文件内的 AppNotification 消费属页面内使用，不算越界）。
