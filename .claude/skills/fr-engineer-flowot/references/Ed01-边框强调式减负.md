# Ed01 — 边框强调式减负

> **E 序列索引**：[[E00-UI骨架地图]] —— 案例层（兜底配方：骨架答不了「这界面该长什么样」时才翻）。

> 何时读：改造纯色填充按钮/icon 容器 / 减负密集按钮区 / 判断「左重右轻」时。
>
> 组件化提示：本配方**已有共享实现**（`lib/core/ui/global/button/main.dart` 的 `EmphasisButton`），详见下方「已有共享实现」一节——**先查共享件，不要再手写 `_outlinedBtnStyle` helper**。判定规则见 《Eb02 分层契约与放置》。

## 一、适用边界（先读）

本方案只适用于**功能型**界面——工具页、表单、设置、密集操作按钮区。
**内容型**页面（游戏中心 / 媒体库 / 作品集）反向操作：封面、Hero 头部、主 CTA 该填充就填充，每条内容还要有专属识别色，见 《Ed04 商店式内容页》。
把本方案当全局禁令套上去，结果就是所有卡片长一样的「demo 形态」。

## 二、红线：边框强调不得有内外底色差

**定义**：「边框强调」= 用**一根有色描边**把一个区域从周围环境中框出来。强调信号 100% 由描边承载。

由此推出唯一成立的判据：

| 项 | 要求 | 判据（自查用） |
| --- | --- | --- |
| 容器底色 | **不设 `color` / `backgroundColor`**（透明），或取值**等于父级表面色** | 把容器底和周边底色并排看，分不出边界 |
| 强调信号 | 只有**描边**（颜色 alpha + 线宽） | 把描边 `BorderSide.none` 后，元素应完全消失、没有任何残留块感 |
| 禁止 | 任何 `accent.withValues(alpha: 0.0x~0.2)` 一类**由强调色派生的浅底** | 一旦有，元素在观感上是「浅色块」而不是「框」 |

**为什么**：底色一旦带 accent 派生色，内外就出现了色差，读者感知到的第一层信息变成「这里有一块颜色」，描边退化成色块的装饰边。这时它已经不是边框强调，而是**填充式强调的低配版**——既没有填充的份量，也失去了边框「只描述轮廓、不参与配色」的克制。

**推论（最容易翻车的一步）**：拿掉 tint 底之后，原先靠 tint「托着」的描边会显得发灰、发飘。所以**底色归零必须同时把描边提上来**（见下节 alpha 表）。只删底色不调描边，等于把强调一起删掉了。

**允许的例外（必须显式声明，不能默认）**：
- 父级本身是图片 / 渐变 / 视频等不可控底 → 用**父级最近一层不透明 `surface`** 兜底，仍不得掺 accent 派生色。
- 语义上确实需要「块」的观感（选中态、已激活、命中区）→ 那是**填充式强调**，走实心填充，不要叠描边假装边框强调。两种形态互斥，同一元素不并置。

## 三、已有共享实现（先查这里）

| 档位 | 共享 API | 位置 | 说明 |
|---|---|---|---|
| 一般功能 | `EmphasisButton.borderEmphasis(context, color:)` | `lib/core/ui/global/button/main.dart:309` | 同色描边 + 同色前景，**底透（无填充）** |
| 破坏性操作 | `EmphasisButton.dangerEmphasis(context)` | 同上 `:57` | 红由 `colorScheme.error` 派生 |
| 次要辅助 | `EmphasisButton.ghostEmphasis(context, color:)` | 同上 `:63` | 透底，仅文字色，无描边 |

**这些是 `ButtonStyle` 工厂**，调用方自己组装 `OutlinedButton`：

```dart
OutlinedButton(
  style: EmphasisButton.borderEmphasis(context, color: colorScheme.primary),
  onPressed: _download,
  child: const Text('下载'),
)
```

- 圆角取自 `Theme.of(context).cardTheme.shape`（`emphasis_button.dart:24-31`，实际落到 `AppRadius.xl=16`），不是 `AppRadius.xs`。
- 描边 alpha：暗色 0.70 / 亮色 0.60；**不设 `backgroundColor`**（见第四节配方表）。
- 全仓 **84 处**调用，**不要再造第三个 helper**。

> ⚠️ **与现有代码的已知偏差**：`borderEmphasis` 上一版给过 `backgroundColor: color.withValues(alpha: isDark ? 0.18 : 0.08)`，这正是第二节要禁掉的 tint 底。按红线，该实现应改为 `backgroundColor: null` 并把描边 alpha 提到 0.70/0.60。**新写代码不要复制 tint 底**；批量收敛共享件前先确认视觉影响面（84 处调用）。

> ⚠️ 语义色（green/blue/orange/red）目前仍散在各调用点（`Colors.blue` / `Colors.red`），尚未收进常量组；需要跨页一致时优先用 `EmphasisButton` 的参数传色，不要复制 alpha 数值。

## 四、核心配方（边框 + 前景，两件套）

**透明底 + 同色描边 + 同色前景。** 底不参与配色，这是与「填充式」的分界。

| 部位 | 取值 | 说明 |
| --- | --- | --- |
| 容器底 | **`null`（不设）** 或父级 `surface` | 内外无底色差 |
| 描边 | alpha **0.55 ~ 0.75**，width **1.5** | 唯一的强调信号；比旧版（0.30~0.50）更高，补偿拿掉 tint 后的轮廓损失 |
| 前景（icon/text） | color 本色 | 与描边同色，整体协调 |

### Icon 容器模板

```dart
final accent = Theme.of(context).colorScheme.primary; // 或功能色

Container(
  width: 52,
  height: 52,
  decoration: BoxDecoration(
    // 不设 color —— 内外同底，强调只由描边表达
    borderRadius: BorderRadius.circular(12),
    border: Border.all(color: accent.withValues(alpha: 0.65), width: 1.5),
  ),
  child: Icon(icon, color: accent, size: 24),
)
```

> 若父级底不是 `surface`（例如暖底卡片内部要再框一个小块），描边 alpha 上限可到 0.8、下限仍守 0.55；**不要用「加深底色」来解决对比不足**。

### 语义色决策：装饰性 vs 功能性（最易错，必读）

**规则相反，不能一刀切。** 这是本序列最核心、最易翻车的判断：

| 元素类型 | 配色策略 | 例子 |
| --- | --- | --- |
| **导航 / 功能入口**（菜单卡 icon、tab、纯装饰） | **统一主题色** `Theme.of(context).colorScheme.primary` | profile 菜单卡片 |
| **功能性**（操作按钮） | **撞色编码语义** | APK / KV / 文件 tab 按钮 |
| **内容条目**（游戏、媒体、作品、模板） | **每条专属识别色**，集中登记在 `const_xxx.dart` 的 slug 表 | 游戏中心卡片封面 → 《Ed04 商店式内容页》 |

功能性语义色对照表（跨页面保持一致）：

| 色 | 语义 | 典型按钮 |
| --- | --- | --- |
| green | 主操作 / 成功 / 写入 | 安装、上传、设置 |
| blue | 查询 / 接收 / 读取 | 检查更新、下载、获取 |
| orange | 暂停 / 警示 | 暂停、停止 |
| **red** | **危险 / 删除** | 取消、删除（**永远保留红**） |
| indigo / teal / deepPurple | 差异化 / 备用操作 | 浏览器下载、继续下载、媒体播放 |

> 注意区分：上表是**功能语义色**，应随主题走；**识别色锁定**（棋盘色等不随主题变化的色）属 《Ec03 特例豁免》，两者不是一回事。

## 五、错误案例（高频坑点）

| 错误操作 | 实际后果 | 正确做法 |
| --- | --- | --- |
| **浅色 accent 底 + 同色描边**（`accent @0.08~0.18` 打底再框一圈） | 内外出现色差，读者先看到「一块浅色」而不是「一个框」；本质是填充式强调的低配版，两头不靠 | 底 `null`，强调全靠描边（第二节红线） |
| 删了 tint 底但描边还用旧 alpha 0.30~0.50 | 轮廓发灰发飘，看起来像随手画的线，强调感丢失 | 描边同步提到 0.55~0.75、width 1.5 |
| 用 `surfaceContainerHighest` / 灰底代替 tint 底 | 换了颜色的填充块而已，内外照样有色差 | 除非父级底就是该色，否则一律透明 |
| 同一元素既填色又描边（选中态叠边框强调） | 两种强调互相稀释，层级反而更模糊 | 填充式与边框式互斥，二选一 |
| 给**导航/功能入口**配彩虹独立色 | 显幼稚、违和、不统一 | 导航 icon 用统一主题色（**内容条目不适用**：作品卡就该有专属色） |
| 给**操作按钮**统一主题色 | 功能无区分、层级丢失 | 按钮用撞色编码语义 |
| 用`.withOpacity(x)` | analyze 报`deprecated_member_use` | 用`.withValues(alpha: x)` |
| 删除/取消按钮也去掉红色 | 危险操作失去警示语义 | 破坏性操作**永远保留 red** |
| 改了按钮忘同步 spinner 颜色 | loading 圈与描边撞色不协调 | `CircularProgressIndicator(color: 同按钮色)` |
| 在**同一片密集按钮区**里留个别纯色填充 CTA | 用户仍投诉「还有纯色」 | 该区域内全转 OutlinedButton；层级靠**颜色 + 位置**。⚠️ 仅限本区域——不要外推到内容页封面 / Hero 头部 |
| helper 第一版写成`(BuildContext, {bool destructive})` | 只能二选一，无法表达多语义色 | 直接收`Color` 参数；或直接用 `EmphasisButton.borderEmphasis(context, color:)` |
| 改造范围蔓延到`IconButton`（纯图标） | 误伤，IconButton 本就不算纯色块 | 只改「填充式」容器/按钮 |
| **手写 `_outlinedBtnStyle` helper** | 与 `EmphasisButton` 形成第二套 alpha 数值，逐渐分叉 | 用 `EmphasisButton`；确需自定义 alpha 时在其基础上改 |

## 六、检查清单

- [ ] **边框强调容器的 `color` / `backgroundColor` 为 `null` 或等于父级表面色——无 accent 派生 tint**
- [ ] **把描边置空后，该元素不残留任何块状色感（消除测试）**
- [ ] 描边 alpha ≥ 0.55、width ≥ 1.5（拿掉底之后必须补偿）
- [ ] 同一元素没有同时使用填充式强调
- [ ] 无残留 `LinearGradient` / 饱和 `color` 填充的 icon 容器
- [ ] 无残留 `ElevatedButton(backgroundColor: Colors.X, foregroundColor: white)` / `FilledButton(backgroundColor: Colors.X)`
- [ ] 装饰元素统一主题色，功能按钮撞色
- [ ] 破坏性操作保留红色
- [ ] 全用 `withValues(alpha:)`，无 `withOpacity`
- [ ] **按钮样式来自 `EmphasisButton`，不是本地 helper**
- [ ] loading / spinner 颜色与所在按钮同步
