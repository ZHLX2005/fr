# A09 · 设置容器与导航目录注册

> 何时读：新增一个可被钉选的入口、改底栏格子 / 容量 / 主题、改设置页本身，或需要判断「某个页面的显示配置归谁管」时。
>
> 核心结论：**设置页是显示配置的最外层容器**。底栏长什么样、首页是谁、某个模块的设置入口挂在哪儿，都由设置页这一层决定；页面本身只负责自己的业务，不直接改全局显示配置。

## 一、四段注册链路

```
demo / 模块  ──①注册──▶  nav_catalog（目录：id → 容器）
                              │
             ②builder 注册 ───┤（破循环依赖，见 nav_builder_registry）
                              ▼
                    nav_pins_notifier（钉选状态：有序 id + 容量）
                              │
                              ▼
                    main_screen（外壳消费：IndexedStack + 底栏 + ⋯）
                              ▲
                              │
                    app_settings_page（设置页：改钉选 / 容量 / 主题）
```

### ① 目录注册：`lib/core/nav/nav_catalog.dart`

- `buildNavCatalog()`（`nav_catalog.dart:49`）每次现算，**不缓存**——目录随 lab bootstrap 变化，缓存由 `invalidateNavCatalogCache()`（`:150`）显式清。
- 核心容器 7 个（`:52`-`:113`），demo 容器由 `demoRegistry.getAll()` 循环生成（`:116`-`:133`）。
- 查询：`navEntryById(id)`（`:141`）、`navEntriesInGroup(group)`（`:152`）。

### ② builder 注册：`nav_builder_registry.dart` + `nav_bootstrap.dart`

- `nav_catalog` 要 import 具体页面、页面又要 import 目录 → 循环依赖。解法：**catalog 只认 id**，具体 Page 在 `registerNavBuilders()`（`nav_bootstrap.dart:6`）里注册，catalog 用 `buildRegisteredNavPage('core-settings', c)`（`nav_catalog.dart:91`）按 id 取。
- 目前只注册了 `core-settings → AppSettingsPage`。新增需要反向依赖的入口时，走这条路，别在 catalog 里直接 import 页面。

### ③ 钉选状态：`lib/core/nav/nav_pins_notifier.dart`

- `navPinsProvider`（`:153`）持有 `NavPinsState`：`capacity`（3 或 4，含末位 ⋯）+ 有序 `pinIds`。
- 派生语义：`visibleSlotCount = capacity - 1`（`:45`）、`visibleIds`（`:47`，底栏可见槽）、`overflowIds`（`:50`，进 ⋯）、`homeId = pinIds.first`（`:59`，首页）、`lastSlotIsSettings`（`:55`，末位槽是否直连设置）。
- 落盘：`SharedPreferences` 的 `nav_pin_ids` / `nav_bar_capacity`（`:11`-`:12`）；`hydrate()`（`:76`）在 `main()` runApp 前调一次。
- 写入口：`setCapacity`（`:103`）/ `setPins`（`:111`）/ `togglePin`（`:118`）/ `reorderPins`（`:129`）/ `removePin`（`:142`，至少留 1 条）。
- 消毒：`sanitizePinIds()`（`:21`）按目录已知 id 过滤 + 去重 + 兜底出厂 `kDefaultNavPins`（`:15`：个人 · Time · 实验室）。

### ④ 外壳消费：`lib/app_lifecycle/main_screen.dart`

- 选中项解析 `_resolveSelected()`（`:39`）：允许「未钉选但有效」的入口（如 ⋯ 里的设置），否则点了没反应。
- 页面实例 `_pageFor()`（`:47`）带 `_pageCache` 缓存——IndexedStack 常驻，State 不能丢；pin 变更时丢弃已移除页的缓存（`:254`）。
- 底栏可见槽 = `pins.visibleIds`（`:261`）；无溢出且设置未被钉选 → 末位槽直连设置（`:267`）。
- 栈：`stackKids`（`:276`）= 可见槽（带 `ValueKey(e.id)`）+ 溢出页（仅 moreSelected 时挂上），`IndexedStack`（`:287`）保持 State 常驻。

## 二、设置机制注册的容器清单

**核心容器**（`nav_catalog.dart:52`-`:113`）：

| id | 标题 | 分组 | 打开的页面 | 说明 |
|---|---|---|---|---|
| `core-time` | Time | core | `FocusHomePage`（`lib/core/focus/focus_home_page.dart`） | 专注 |
| `core-lab` | 实验室 | core | `LabPage` | 工具浏览壳（`kLabNavId`，`:12`） |
| `core-games` | 游戏中心 | core | `GameCenterPage` | 封面浏览壳 |
| `core-profile` | 个人 | core | `ProfilePage` | Banner / 彩蛋（可钉选） |
| `core-settings` | 设置 | core | `AppSettingsPage` | **主题与快捷导航**（`kSettingsNavId`，`:28`；builder 由 `nav_bootstrap.dart:7` 注册） |
| `core-theme` | 主题 | core | `ThemePage` | 外观 |
| `core-ai` | AI 中心 | core | `HomePage` | 助手 / Agent / 小票 / pi（整块作为核心组一个入口，不拆子元素） |

**demo 容器**：`demoRegistry.getAll()` 里每个 demo = 一个可钉选单元，id = `demo:<slug>`（`nav_entry.dart:16` 的 `demoNavId`），分组按 `DemoType` 落到 lab / game，图标解析顺序见 `nav_catalog.dart:3`-`:8`（`DemoPage.navIcon` → `kGameMeta[slug].icon` → 类型默认 icon）。

> 新增页面要能被钉选，**登记在 catalog 里**，不是在设置页里加一行——设置页只消费目录。

## 三、设置页本身的三块

`lib/screens/settings/app_settings_page.dart`：

1. **钉选网格**（`pinned_grid.dart`）——只显示已钉的格子；长按拖动排序（`ReorderableBuilder`），拖到右下角**投放条**删除（148×56 横向条，见 `const_settings.dart` 的 `kSettingsTrashBar*`）。格子数据 = `navPinsProvider.pinIds` 映射 `navEntryById`（`app_settings_page.dart:40`）。
2. **通用项卡片** `_GeneralCard`：主题、底栏容量（3/4）、远程输入（模块设置入口）。
3. **管理弹窗** `pin_editor_sheet.dart`——全量清单：按 `NavGroup` 分组 + 搜索（`:47` `_match`）+ 点选即钉/拔；数据来自 `navEntriesInGroup()`（`:177`）。**排序不在这里**，排序在主页面的拖动网格。

## 四、改动纪律与坑

- **id 是持久化键**：用展示文案当 id = 用户布局全部失效。核心 id 见上表，demo id 用 `demoNavId(slug)`，两处各写字面量会「请求挂在 id A、目录注册 id B」静默失联。
- **别绕过 catalog**：页面里写死 `Navigator.push(某具体页面)` 会让「设置 → 钉选 → 打开」这条链断掉；入口一律走 `navEntryById(id)?.builder(context)`。
- **显示配置归设置**：底栏格子 / 容量 / 主题 / 模块设置入口都从设置页进出。页面要改全局显示配置 → 改设置页机制（catalog + pins），不要在页面里塞私有的持久化开关（这正是远程输入这次被改成「布局全部进设置」的原因）。
- **末位槽直连设置**：`lastSlotIsSettings`（`nav_pins_notifier.dart:55`）要求设置**没被钉在可见槽**，否则同一入口出现两次。
- **底栏不是 Scaffold.bottomNavigationBar**：主壳底栏是 Stack 浮层（`main_screen.dart:313`）。页面避让用 `QuickNavBottomBar.bodyBottomReserve(context)`，**勿写入 MediaQuery.padding**（SafeArea 会吃掉后露出 Scaffold 白条）。
- **底栏显隐请求按 nav id 记名**（`bottomBarVisibilityProvider`）：IndexedStack 里钉选页 State 全部常驻，裸 bool 会把离场页面的请求泄漏给别的页。
- **环形依赖**：目录 ↔ 页面用 `nav_builder_registry` 破，不要在 catalog 里直接 import 页面。
