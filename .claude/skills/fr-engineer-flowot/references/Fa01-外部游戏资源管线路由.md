# Fa01 — 外部游戏资源管线路由

> Fa 是 F 的外部资产子序列；Fa01 只做路由，端到端细节分别在 Fa02–Fa04。
>
> 核心链路：公开文件上传得到 `file_id` → 生成/合并资源 metadata → 写入公开 KV 索引 → 客户端读取并缓存。远程发布是有外部副作用的动作，不会因为本地有脚本就自动执行。

| [[Fa03-加载架构与文件地图]] | 理解客户端目录、fallback、KV merge 和缓存位置时 |

## 资源发布工具

脚本在 `.claude/skills/fr-engineer-flowot/scripts/`：

| 脚本 | 用途 |
|---|---|
| `add_skin.py` | 棋类皮肤/游戏中心封面上传和索引合并 |
| `add_emoji_pack.py` | 表情包上传与索引更新 |

执行修改远端 API/KV 的命令前：确认目标后端、账号/token、资源目录、索引 key 和预期变更；优先查看脚本参数及 dry-run。`retag_existing.py` 有 `--dry-run`；迁移脚本先运行 `--dry-run`。若不确定是否会写远端，先阅读脚本实现并停在预览阶段。

## 公开 KV 关键约束

- File upload 与 KV 写入需要授权；客户端下载 public file/KV 使用匿名读取路径。
- 索引通常是全量数组覆盖；发布脚本负责读旧值、合并再全量写回。手动写入前先确认目标 key 和覆盖语义。
- tag 更新可能是 replace 语义；补 tag 前核对旧 tags 与实际 file 所属 group，不能假设所有 file 在共享 KV group。
- 具体 endpoint、schema、资源清单以 Fa02/Fa03 与当前脚本/客户端实现核对；此路由页不重复维护端到端 SOP。
