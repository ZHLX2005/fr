# Ba01 — 消息策略模式

> **适用范围**：`lib/services/message_strategy/` 通用消息渲染管线。本 ref 讲“消息如何渲染/注册”，不是会话数据持久化规范；后者见 [[Ba02-IM会话持久化规范]]。
>
> 当前真实 Chat 入口在 `lib/screens/containers/ai_container.dart` 的 entries 中（含 Agent、Format、小票 OCR、系统事件与 pi 等）；不要按历史文档的固定数量推断。

## 架构

```text
IMessageData（type 由数据层定义）
  → MessageWidgetStrategy<T>（渲染 + createMockData）
  → MessageWidgetFactory（type → strategy，O(1) 查找）
  → GetIt DI 注册（registerMessageStrategies()）
```

## 添加新消息类型

1. **数据层**：在 `lib/services/message_strategy/data/` 实现 `IMessageData`；`type` 只在数据层定义。

```dart
class XxxMessageData implements IMessageData {
  const XxxMessageData(this.content);
  final String content;

  @override
  String get type => 'xxx';
}
```

2. **Strategy**：在 `lib/services/message_strategy/strategies/` 实现渲染。交互型消息（输入框/选项列表）使用私有 `_StatefulWidget` 管理未确认局部状态；确认后进入锁定渲染。

```dart
class XxxMessageWidgetStrategy extends MessageWidgetStrategy<XxxMessageData> {
  @override
  Widget build(BuildContext context, XxxMessageData data) => _XxxContent(data: data);

  @override
  XxxMessageData createMockData() => const XxxMessageData('mock');
}

class _XxxContent extends StatefulWidget {
  const _XxxContent({required this.data});
  final XxxMessageData data;

  @override
  State<_XxxContent> createState() => _XxxContentState();
}

class _XxxContentState extends State<_XxxContent> {
  bool _isFixed = false;
  String _fixedValue = '';

  void _handleConfirm() {
    final value = _value();
    if (value.isEmpty) return;
    setState(() {
      _fixedValue = value;
      _isFixed = true;
    });
  }

  @override
  Widget build(BuildContext context) =>
      _isFixed ? _buildFixedContent() : _buildInputContent();
}
```

> **演示态 vs 真实入口**：`_isFixed` 只锁 UI 展示。消息要落进真实 chat 会话时，确认结果必须按 [[Ba02-IM会话持久化规范]] 写入会话模型并回写持久层。

3. **导出**：`data/data.dart`、`strategies/strategies.dart` 各加 `export 'xxx_*.dart';`。
4. **DI 注册**：在 `lib/services/message_strategy/di/message_strategy_di.dart` 的策略实例列表追加；确认 `registerMessageStrategies()` 在应用初始化路径被调用且只调用一次。
5. **验证**：`flutter analyze` 0 error；跑/补 type→strategy 映射与 mock 数据测试；真实入口再按 Ba02 检查确认状态持久化。

## 常见错误

| 错误 | 后果 | 修复 | 验证 |
|---|---|---|---|
| strategy 里写 `@override dispose` | `MessageWidgetStrategy` 基类没有 dispose，analyze 报 invalid override | 去掉 `@override`；资源释放交给调用方生命周期 | `flutter analyze` |
| strategy 定义 `String get type` | 与数据层重复，DI 映射可能绑错 | `type` 只在 `XxxMessageData`；strategy 只渲染 | DI 映射测试 |
| `withOpacity(...)` | Flutter 已废弃该 API | `Colors.grey.withValues(alpha: 0.4)` | analyze 无 deprecation |
| DI 对每个 strategy 调两次 `createMockData()` | mock 重复构造/不一致 | 单次循环里先取 mock，再同时填 strategy 与 mock map | DI 初始化单测 |
| 漏 `registerMessageStrategies()` | 渲染 factory 查不到 strategy，消息显示失败 | 在应用初始化注册；确认无重复注册 | 发送/渲染冒烟测试 |
| 确认态只存 `_isFixed` | 重启后回到未确认 | 真实入口按 Ba02 三步契约回写 Store | 重启恢复锁定态 |

## 错误码/异常处理边界

消息渲染层没有 HTTP 状态码；网络/服务端错误由具体入口（如 pi 的 endpoint、Notion/GoFrame endpoint）抛出并按其 API 层处理。strategy 内不要吞异常：异步回调里优先检查 `mounted`，错误统一交给调用方提示或日志。
