# Eb02 — FR 主题系统架构与数据流

> E 大序列的主题子序列总路由见 [[Eb01-主题架构路由]]。本页记录架构与源码定位，不替代 Eb03 修改 SOP。

## 设计主线

FR 主题系统以 ColorScheme 为派生基础，通过各 Strategy 和 ThemeExtension 为页面/组件提供有类型的颜色访问。颜色原料从 tokens 开始，经 strategy、app theme 组装、ThemeExtension 注入后由 context API 消费。

```text
design tokens / palettes
    → Theme / ColorScheme
    → domain ColorStrategy
    → ThemeStrategyFactory + ThemeExtension
    → app_theme.dart / theme provider
    → context.colors / boardColors / chessColors / tetrisColors / teamAvatar / torchProtect
```

- 低层 token 不依赖高层组件或页面；strategy 负责把主题 scheme 与领域色彩角色组合。
- 组件/页面通过 context color API 或标准 `Theme.of(context).colorScheme` 取色，不各自再造调色板。
- 固定识别色业务（例如 Tetris 方块/Team Avatar）是有明确原因的例外，按 Eb05；不能把所有颜色硬编码都归为例外。

## 当前源码地图

| 层 | 真实路径 | 职责 |
|---|---|---|
| 原料/色板 | `lib/design_tokens/color/` | Board、Chess、Team、Tetris、Torch、Sudoku、各主题 palettes 与 `AppColorsExtension` |
| 策略契约/实现 | `lib/core/theme/colors/strategy/` | Color、Board、Chess、Tetris、TeamAvatar、TorchProtect 等角色策略 |
| 策略工厂 | `lib/core/theme/colors/factory.dart` | 根据主题创建项目颜色策略 |
| ThemeExtension | `lib/core/theme/extensions/` | 将策略实例注入 ThemeData，供上下文读取 |
| 主题装配 | `lib/core/theme/app_theme.dart` | 主题 mode → ColorScheme、extension 与 ThemeData |
| 主题状态 | `lib/core/theme/state/theme_provider.dart` | theme mode 状态、hydrate 与 provider |
| 消费 API | `lib/core/theme/context/` | `context.colors`、`boardColors`、`chessColors`、`tetrisColors`、`teamAvatar`、`torchProtect`、`sudokuColors`（Sudoku 策略/context 已存在，但 factory/app_theme 尚未注入其 extension，context 走 factory fallback——扩展前先读此 caveat） |

当前主题集合、策略数量、角色字段应以实际目录与代码为准；本文快照会随实现演进，不能以旧版本数字替代代码事实。

## 主题切换数据流

```text
用户选择 AppThemeMode
   ↓
themeNotifierProvider / ThemeNotifier 更新状态
   ↓
themeDataProvider 调用 AppTheme 组装 ThemeData
   ↓
ThemeStrategyFactory 从新 ColorScheme 创建各 domain strategy
   ↓
ThemeExtension 注入 MaterialApp 的 ThemeData
   ↓
widget 读取 context.*Colors 或 Theme.of(context).colorScheme
```

策略缓存和默认构造路径由项目实现决定；使用现有 factory/`Default...Strategy.of(scheme)` 入口，不绕过缓存策略自行构造副本。
