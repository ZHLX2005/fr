# C00 — RelayLua 大序列路由

> C 在 FR 工程总路由中只代表 RelayLua。子序列：Ca（通用契约）、Cb（双人对战游戏）、Cc（多人大厅）；成员 `Ca01`/`Cb01`/`Cc01` 命名，子序列自身不设 `00`，**本文件集中维护所有子序列路由与动线**。

## 需求动线表（诉求 → 顺序读）

| 需求 | 动线 |
|---|---|
| **任何 v3 互联网房间**（必读地基） | [[Ca01-服务端权威状态]]（原则）→ [[Ca04-Lua房间契约检查表]]（写脚本前过表） |
| **双人对战游戏**（2 人轮流 + 有胜负） | [[Ca01-服务端权威状态]] → [[Ca04-Lua房间契约检查表]] → [[Cb01-双人对战房间模板]]（§8 从零 checklist）→ [[Ca02-命名与GameMeta]] → 《A05-游戏中心扩展》§加新游戏 → 《Ed08-大厅与房间就绪》 → 《V00-工程收尾与排障动线》§1 收尾 |
| **社交场景双人对战**（双方输同一房间号，先到为房主） | [[Ca01-服务端权威状态]] → [[Ca04-Lua房间契约检查表]] → [[Cb02-社交房间号模式]] → [[Cb01-双人对战房间模板]] → [[Ca02-命名与GameMeta]] → 《A05-游戏中心扩展》§加新游戏 → 《V00-工程收尾与排障动线》§1 |

## 上下游规则

- 任何 v3 业务先读 [[Ca01-服务端权威状态]]（原则）并过 [[Ca04-Lua房间契约检查表]]（契约）；新增游戏登记 = [[Ca02-命名与GameMeta]]（叫什么）+ 《A05-游戏中心扩展》（注册机制，唯一事实源）。
- [[Cb01-双人对战房间模板]] 综合调用 Ca01/Ca03、Cb02/Cb03 和 Cc01；只在匹配的业务变体时加载相应成员。
- C 序列只含 RelayLua；Timetable/WebRTC 等其他子系统不属于本序列，也不要因编号相似混入。
