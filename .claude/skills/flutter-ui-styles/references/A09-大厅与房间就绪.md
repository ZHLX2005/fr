# A09 · 大厅与房间就绪

> 何时读：象棋（及共享 GameLobby）入口页、房间等待/就绪、匹配中转场；要对齐 `feature-list-and-lobby.html` / `game-surfaces-palettes.html` 的 lobby · room 块。
>
> 代码锚点：`kChessLobbySpec`、房间就绪 UI（如 `ChessRoomPage` 准备态）。

## 一、实现思路

### 大厅入口栈（上→下单一重心）

1. **Mark**：约 88×88，圆角 ~28，`primaryContainer` 或主题纹样  
2. **标题 + 一句副文**  
3. **表单卡**：圆角 **22–24**，浮在暖底（[[A06-Zen浮卡少描边]]）  
4. **主 CTA**：全胶囊，clay/`tertiary` 或 `primary`（[[A08-胶囊与方圆角CTA]]）  
5. **弱 hint** 一行，居中 `textMuted`

不要在第一屏再塞规则长文、统计条、第二主按钮。

### 房间就绪卡

| 元素 | 规格 |
| --- | --- |
| 外卡 | 圆角 ~20–24，surface 浮起 |
| 房间码 | letter-spacing 加大的 code pill |
| 规则 | 小 chip（执白/残局等） |
| 座位行 | 头像 + 名；**就绪**用 tertiary/clay **描边**强调，非整行填色 |
| 动作 | 方圆角 **12** 的 stacked Filled / Outlined（就绪、发牌）——此处不用全胶囊抢大厅仪式 |

### 匹配笔刷转场（可选）

原型：`CustomPainter` / canvas 鬃刷从 TL→BR 扫过，再接 sage/`primary` 洗白。

- 洗色必须与目标页 scaffold **同色**，否则闪一帧异色。  
- `matching` 态锁交互；结束再 `push`/`replace` 进房。  
- 无真实 bug 时不必单独建 B 类 ref；race 仍走 [[B01-嵌套sheet异步加载防race]]。

### 主题

游戏表面必须吃 `ColorScheme`，禁止写死 sage/clay hex → [[C01-游戏表面ColorScheme契约]]。

## 二、踩坑总结

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 大厅第一屏多 CTA + 规则墙 | 无视觉重心（原型 brief 点名） | 只留一个胶囊主按钮 |
| 就绪座位整行 primary 填充 | 过重、难扫谁未就绪 | 就绪 = 细描边 / chip |
| 房内主按钮也用 999 胶囊 | 与大厅仪式撞车 | 房内方圆角 12 stacked |
| 笔刷洗色 ≠ 下一页底色 | 闪白/闪绿 | wash = `Theme.scaffoldBackgroundColor` |
